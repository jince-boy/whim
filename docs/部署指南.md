# 部署指南

本文按“配置环境变量和密钥 → 本地构建镜像 → 导出并上传 → 服务器加载 → 启动验证 → 后续更新”的顺序操作。本地示例使用 Windows PowerShell，服务器示例使用 Linux Shell；命令中的服务器 IP、账号、密码和密钥需要替换为实际值。

## 一、部署前准备

本地安装并启动 Docker Desktop，切换到 Linux 容器模式，确认可以使用 Docker Compose。生成密钥时需要 Node.js；镜像构建所需的 JDK、Maven、Node.js 和 pnpm 由 Dockerfile 提供，不需要在服务器安装。

服务器需要已安装 Docker Engine 和 Compose 插件，并准备好 MySQL、Redis。本项目的 Compose 只启动前后端，不创建数据库和缓存服务。服务器镜像架构应与本地构建目标一致；例如服务器为 ARM64 时，给本地两个 `docker build` 命令都添加 `--platform linux/arm64` 后再构建、导出。

在本地 PowerShell 检查工具：

```powershell
docker version
docker compose version
node --version
```

以下表格是仓库 Compose 的默认部署布局：

| 项目 | 后端 | 前端 |
| --- | --- | --- |
| 本地 Compose | 根目录 `compose.yaml` | `whim-vue/compose.yaml` |
| 镜像标签 | `whim-backend:local` | `whim-frontend:local` |
| 服务器目录 | `/opt/whim/backend` | `/opt/whim/frontend` |
| 宿主机端口 | `9192` | `9191` |
| 容器端口 | `8089` | `80` |
| 共享 Docker 网络 | `my-network` | `my-network` |

## 二、配置环境变量

### 2.1 先区分三个配置位置

| 配置位置 | 用途 | 何时生效 |
| --- | --- | --- |
| 根目录 `compose.yaml` 的 `services.backend.environment` | 数据库、Redis、JWT、日志等后端容器环境变量 | 重新创建后端容器 |
| 根目录 `.env` | 覆盖后端 Compose 已用 `${变量名:-默认值}` 引用的上传参数、云存储加密密钥 | 重新创建后端容器 |
| `whim-vue/.env` | 前端构建使用的公钥、标题、接口前缀，以及前端 Compose 的部署参数 | 构建参数需重建前端镜像；运行参数需重建容器 |

`.env` 不会把任意变量自动传进容器。当前数据库、Redis、JWT 等值直接写在后端 Compose 的 `environment` 中，要修改对应条目；只在根目录 `.env` 中添加同名变量不会覆盖这些固定值。使用 `${...}` 引用的条目才会读取宿主环境或 `.env`，同名宿主环境变量优先。[Compose 环境变量说明](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/)

首次配置时，在项目根目录执行下面的命令。已有 `.env` 时保留原文件并编辑，不要用模板覆盖现有密钥：

```powershell
if (-not (Test-Path -LiteralPath .\.env)) {
    Copy-Item -LiteralPath .\.env.example -Destination .\.env
}
if (-not (Test-Path -LiteralPath .\whim-vue\.env)) {
    Copy-Item -LiteralPath .\whim-vue\.env.example -Destination .\whim-vue\.env
}
```

### 2.2 后端数据库、Redis 和端口

打开根目录 `compose.yaml`，在 `services.backend.environment` 中核对以下值：

| 环境变量 | 当前配置或填写要求 |
| --- | --- |
| `MYSQL_HOST` | 当前为 `mysql8.2`；同网络填写 MySQL 容器名，外部数据库填写可达地址 |
| `MYSQL_PORT` | 当前为 `3306` |
| `MYSQL_DB` | 当前为 `whim`；数据库应提前创建 |
| `MYSQL_USER` | 填写实际数据库账号，需具有业务访问及 Flyway 迁移权限 |
| `MYSQL_PASSWORD` | 填写对应账号密码 |
| `MYSQL_SSL_MODE` | 当前为 `REQUIRED`，要求 MySQL 支持 TLS；使用 `VERIFY_IDENTITY` 时还需配置可信证书及匹配的主机名 |
| `REDIS_HOST` | 当前为 `redis`；填写同网络容器名或可达地址 |
| `REDIS_PORT` | 当前为 `6379` |
| `REDIS_DB` | 当前为 `0` |
| `SPRING_DATA_REDIS_SSL_ENABLED` | 当前为 `false`；Redis 使用 TLS 时按实际部署调整 |
| `SATOKEN_JWTSECRETKEY` | 填写固定的 JWT 签名密钥，生成方式见第三节 |
| `FILE_STORAGE_PATH` | 保持为容器内路径 `/app/data/files`，对应现有卷挂载 |

Redis 无密码时，不添加用户名或密码变量。Redis 启用认证后，在同一个 `environment` 下添加 `SPRING_DATA_REDIS_PASSWORD`；只有使用命名 ACL 用户时才添加 `SPRING_DATA_REDIS_USERNAME`。不要以空字符串表示“无密码”。

直接写在 Compose 中的值如果包含 `$`，需写成 `$$`，避免触发 Compose 插值。YAML 字符串使用引号包裹。文档中的示例值不能代替真实密码。

后端宿主机端口在 `ports` 中配置，当前为 `"9192:8089"`，左侧是服务器对外端口。前端通过 Docker 网络中的 `whim-api:8089` 访问后端，因此仅修改宿主机端口时，无需修改前端的容器内连接地址。

### 2.3 后端上传大小和分片规则

编辑根目录 `.env`。默认配置可以直接沿用：

```dotenv
FILE_STORAGE_SECRET_KEY=
FILE_STORAGE_MAXFILESIZE=200MB
SPRING_SERVLET_MULTIPART_MAXFILESIZE=200MB
SPRING_SERVLET_MULTIPART_MAXREQUESTSIZE=201MB

FILE_MANAGEMENT_UPLOADPARTSIZERULES_0_MINFILESIZE=0B
FILE_MANAGEMENT_UPLOADPARTSIZERULES_0_PARTSIZE=8MB
FILE_MANAGEMENT_UPLOADPARTSIZERULES_1_MINFILESIZE=100MB
FILE_MANAGEMENT_UPLOADPARTSIZERULES_1_PARTSIZE=16MB
FILE_MANAGEMENT_UPLOADPARTSIZERULES_2_MINFILESIZE=1GB
FILE_MANAGEMENT_UPLOADPARTSIZERULES_2_PARTSIZE=32MB
FILE_MANAGEMENT_UPLOADPARTSIZERULES_3_MINFILESIZE=10GB
FILE_MANAGEMENT_UPLOADPARTSIZERULES_3_PARTSIZE=64MB
```

- `FILE_STORAGE_MAXFILESIZE` 是单文件总大小上限，普通上传和分片上传都受它限制。
- 两个 `SPRING_SERVLET_MULTIPART_...` 分别限制单次请求中的文件和整个请求体，请求体需要为表单封装留出空间。
- `MINFILESIZE` 是档位下限，达到该大小时使用对应的 `PARTSIZE`。下限从 `0B` 开始严格递增，单片允许 `5MB` 至 `64MB`，末片按剩余大小上传。
- 配置中的 `MB`、`GB` 分别按 MiB、GiB 计算。默认总上限为 200 MiB，较大档位要提高总上限后才可能使用。
- Compose 会补齐并传入完整四档；调整分片规则只影响新建任务，已有任务沿用创建时保存的大小。

例如允许文件管理页面上传 1 GiB 文件，只需将 `FILE_STORAGE_MAXFILESIZE` 改为 `1GB`；恰好 1 GiB 的文件使用 32 MiB 分片，现有单次请求限制足够。若业务接口一次上传整个 1 GiB 文件，还需同步提高两个 multipart 限制、前端 Nginx 的 `client_max_body_size` 和外层网关限制。

服务器仅使用本地存储、默认上传参数时，可以不提供后端 `.env`；启用云存储时必须填写加密密钥，见第三节。

### 2.4 前端构建和运行配置

编辑 `whim-vue/.env`：

| 变量 | 填写要求 | 生效方式 |
| --- | --- | --- |
| `VITE_REQUEST_ENCRYPTION_PUBLIC_KEY` | 必填，与后端私钥配对的单行 Base64 公钥 | 重新构建前端镜像 |
| `VITE_API_BASE_URL` | 默认 `/api`，以 `/` 开头且末尾不带 `/` | 同时用于前端构建和 Nginx 运行配置 |
| `VITE_APP_TITLE` | 网站标题 | 重新构建前端镜像 |
| `VITE_APP_DESCRIPTION` | 网站介绍 | 重新构建前端镜像 |
| `VITE_APP_COPYRIGHT` | 版权文案 | 重新构建前端镜像 |
| `FRONTEND_IMAGE` | 服务器运行的镜像标签，默认 `whim-frontend:local` | 必须与本地 `docker build -t` 指定的标签一致 |
| `BACKEND_ADDRESS` | 默认 `whim-api:8089`，不带协议和路径 | 重新创建前端容器 |
| `FRONTEND_PORT` | 默认 `9191` | 重新创建前端容器 |
| `FRONTEND_BIND_ADDRESS` | 默认 `0.0.0.0` | 重新创建前端容器 |
| `SHARED_NETWORK_NAME` | 默认 `my-network`，需与后端网络一致 | 重新创建前端容器 |
| `NGINX_TEMPLATE_DIR` | 默认 `/opt/whim/frontend/nginx/templates` | 重新创建前端容器 |

`VITE_` 构建参数会进入浏览器资源，只能填写公开配置，不能放入私钥、数据库密码或云存储加密密钥。前端 Dockerfile 通过 `--build-arg` 接收这些值，不把本地 `.env` 复制进镜像。`docker build` 不会自动读取 `.env`，第四节提供了读取现有配置并传入构建参数的完整命令。

同一服务器部署时沿用默认 `BACKEND_ADDRESS`。前后端位于不同服务器时，改为后端可达的私网地址和宿主机端口，例如 `10.0.0.10:9192`。如果修改接口前缀，服务器前端运行时也必须提供与构建时相同的 `VITE_API_BASE_URL`。

## 三、配置三类密钥

| 密钥 | 用途 | 配置位置 | 更新时的要求 |
| --- | --- | --- | --- |
| 请求加密 RSA 私钥 / 公钥 | 后端解密前端 JSON 请求 | 后端 `application.yml` 私钥、前端 `.env` 公钥 | 必须配对；按本指南流程重建、同时发布前后端镜像 |
| JWT 签名密钥 | 登录令牌相关签名 | 后端 Compose 的 `SATOKEN_JWTSECRETKEY` | 保持固定，轮换会影响仍使用旧签名的令牌 |
| 云存储凭据加密主密钥 | 加密数据库中的云存储凭据 | 后端 `.env` 的 `FILE_STORAGE_SECRET_KEY` | 必须长期保留，直接更换后旧凭据无法解密 |

这三类密钥用途不同，分别生成、分别保存。首次部署配置自己的密钥；更新已有环境时沿用该环境原来的密钥，不要每次构建或重启都重新生成。

### 3.1 请求加密 RSA 密钥

在项目根目录的 PowerShell 中执行：

```powershell
node .\scripts\generateRequestKey.mjs
```

脚本输出一对 3072 位 RSA 密钥，只输出配置，不自动写入文件。

1. 将 `private-key` 的完整内容复制到 `whim-start/src/main/resources/application.yml` 的 `whim.request-encryption.private-key`。
2. 将 `VITE_REQUEST_ENCRYPTION_PUBLIC_KEY` 的完整内容复制到 `whim-vue/.env` 的同名变量。
3. 两项均使用不带头尾标记、不换行的 Base64 字符串；私钥为 PKCS#8 DER，公钥为 SPKI DER。
4. 完成配对后，再执行第四节的镜像构建。

当前后端 Compose 不额外传入请求加密私钥，运行时使用镜像中已经配置的私钥；服务器不必再次填写。前端公钥已经编译进静态资源，服务器只运行镜像时也无需再次填写公钥。后端镜像包含私钥，镜像归档与密钥配置都应限制访问。

如果采用运行时私钥覆盖，需要明确在后端 Compose 的 `environment` 中添加 `WHIM_REQUESTENCRYPTION_PRIVATEKEY`，填写实际完整私钥，不能设置为空；只把它写入当前根目录 `.env` 不会自动传入容器。前端仍必须使用配对公钥重新构建。协议细节见[请求加密说明](请求加密说明.md)。

### 3.2 JWT 签名密钥

在本地 PowerShell 中生成随机字符串：

```powershell
node -e "console.log(require('node:crypto').randomBytes(64).toString('hex'))"
```

将输出填写到根目录 `compose.yaml` 的 `services.backend.environment.SATOKEN_JWTSECRETKEY`。部署到服务器的 Compose 应保留同一值；多实例使用同一密钥。

### 3.3 云存储凭据加密主密钥

使用阿里云 OSS、MinIO 等云存储前，在本地生成 32 字节随机密钥：

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
```

将输出填写到根目录 `.env`：

```dotenv
FILE_STORAGE_SECRET_KEY="此处填写生成的完整Base64密钥"
```

随后把这个后端 `.env` 一起部署到服务器，并与数据库备份一起妥善保存。它不是云平台的 AccessKey，也不是 RSA 私钥。云平台凭据在系统的存储配置页面填写，后端使用该主密钥加密后保存。仅使用本地存储时可保持为空。

## 四、在本地构建镜像

以下操作从项目根目录开始，使用 `docker build -t` 构建镜像，服务器使用 Compose 启动容器。`-t` 指定镜像名称和标签，`-f` 指定 Dockerfile，命令末尾的路径是构建上下文。

先校验两个 Compose 文件：

```powershell
docker compose --file .\compose.yaml config --quiet
docker compose --file .\whim-vue\compose.yaml --env-file .\whim-vue\.env config --quiet
```

`config --quiet` 只校验 Compose 解析，不检查数据库连接、密钥配对或应用是否能成功启动，也不会输出完整配置中的密码。

构建后端：

```powershell
docker build -t whim-backend:local -f .\Dockerfile .
```

后端 Dockerfile 使用构建阶段完成 Maven 打包，再把应用 JAR 放入 JDK 25 对应的运行镜像，最终标签为 `whim-backend:local`。

构建前端时，先用 Compose 的 `config` 命令解析现有前端 `.env` 和 `build.args`，再将结果传给 `docker build`。解析配置这一步不会构建镜像或启动容器，也不需要重复复制公钥：

```powershell
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new()
$frontendComposeJson = docker compose --file .\whim-vue\compose.yaml --env-file .\whim-vue\.env config --format json
if ($LASTEXITCODE -ne 0) { throw '读取前端构建配置失败' }
$frontendBuildArguments = ($frontendComposeJson | ConvertFrom-Json).services.frontend.build.args
if ([string]::IsNullOrWhiteSpace($frontendBuildArguments.VITE_REQUEST_ENCRYPTION_PUBLIC_KEY)) {
    throw '请先在 whim-vue/.env 中配置请求加密公钥'
}

docker build -t whim-frontend:local -f .\whim-vue\Dockerfile `
    --build-arg "VITE_API_BASE_URL=$($frontendBuildArguments.VITE_API_BASE_URL)" `
    --build-arg "VITE_REQUEST_ENCRYPTION_PUBLIC_KEY=$($frontendBuildArguments.VITE_REQUEST_ENCRYPTION_PUBLIC_KEY)" `
    --build-arg "VITE_APP_TITLE=$($frontendBuildArguments.VITE_APP_TITLE)" `
    --build-arg "VITE_APP_DESCRIPTION=$($frontendBuildArguments.VITE_APP_DESCRIPTION)" `
    --build-arg "VITE_APP_COPYRIGHT=$($frontendBuildArguments.VITE_APP_COPYRIGHT)" `
    .\whim-vue
```

上面的反引号是 PowerShell 续行符，必须位于行末，后面不要添加空格。前端构建上下文是 `.\whim-vue`，与后端使用项目根目录不同。

前端 Dockerfile 使用 Node.js 26、pnpm 12.8.1 构建静态资源，再放入 Nginx 镜像。镜像标签由 `-t whim-frontend:local` 指定，与后面的导出、加载步骤一致。仅修改 `.env` 中的 `FRONTEND_IMAGE` 不会改变这条直接构建命令的标签；使用自定义标签时，需同步修改 `-t`、导出命令及服务器运行配置。

确认两个镜像都存在：

```powershell
docker image inspect whim-backend:local whim-frontend:local --format "{{.RepoTags}} {{.Os}}/{{.Architecture}}"
```

构建说明：[Docker 构建命令](https://docs.docker.com/reference/cli/docker/buildx/build/)、[构建参数](https://docs.docker.com/build/building/variables/)。

## 五、导出镜像并整理部署文件

仍在项目根目录的同一个 PowerShell 窗口中执行：

```powershell
$releaseDirectory = Join-Path $env:USERPROFILE 'whim-release'
New-Item -ItemType Directory -Force -Path $releaseDirectory, "$releaseDirectory\backend", "$releaseDirectory\frontend"

docker image save --output "$releaseDirectory\whim-images.tar" whim-backend:local whim-frontend:local

Copy-Item -LiteralPath .\compose.yaml -Destination "$releaseDirectory\backend\compose.yaml"
Copy-Item -LiteralPath .\whim-vue\compose.yaml -Destination "$releaseDirectory\frontend\compose.yaml"
if (Test-Path -LiteralPath .\.env) {
    Copy-Item -LiteralPath .\.env -Destination "$releaseDirectory\backend\.env"
}

Get-FileHash -LiteralPath "$releaseDirectory\whim-images.tar" -Algorithm SHA256
```

`docker image save` 导出的是镜像及标签，后续用 `docker image load` 恢复；不要使用容器文件系统导出的 `docker export` 替代。[镜像导出说明](https://docs.docker.com/reference/cli/docker/image/save/)

默认部署文件结构：

```text
whim-release/
├── whim-images.tar
├── backend/
│   ├── compose.yaml
│   └── .env                  # 覆盖上传配置或启用云存储时提供
└── frontend/
    └── compose.yaml
```

前端公钥和标题已在镜像中，不需要把前端的本地构建 `.env` 整份上传。如果前端使用了非默认运行参数，在发布目录的 `frontend/.env` 中只填写实际需要的运行参数，例如：

```dotenv
VITE_API_BASE_URL=/api
BACKEND_ADDRESS=whim-api:8089
FRONTEND_PORT=9191
FRONTEND_BIND_ADDRESS=0.0.0.0
SHARED_NETWORK_NAME=my-network
NGINX_TEMPLATE_DIR=/opt/whim/frontend/nginx/templates
```

这些值应与目标服务器一致，其中接口前缀必须与前端构建时一致。使用自定义镜像标签时，还需在这里填写相同的 `FRONTEND_IMAGE`。

## 六、上传到服务器

可使用文件传输工具，将发布目录内容上传到 `/opt/whim`。也可以在前述 PowerShell 窗口执行以下命令，将服务器地址改为实际地址：

```powershell
$deploymentServer = 'root@服务器IP'
ssh $deploymentServer 'install -d -m 0755 /opt/whim/backend /opt/whim/frontend'
scp "$releaseDirectory\whim-images.tar" "$($deploymentServer):/opt/whim/whim-images.tar"
scp -r "$releaseDirectory\backend" "$releaseDirectory\frontend" "$($deploymentServer):/opt/whim/"
```

上传后服务器目录应为：

```text
/opt/whim/
├── whim-images.tar
├── backend/
│   ├── compose.yaml
│   └── .env                  # 使用后端环境文件时存在
└── frontend/
    ├── compose.yaml
    └── .env                  # 覆盖前端运行参数时存在
```

首次部署后，服务器上的配置和密钥应作为该环境的固定配置保存。更新部署时先备份现有配置，仅同步明确需要修改的条目，不用本地模板覆盖服务器已有密钥。

## 七、准备服务器基础环境

从本节开始，所有命令在 Linux 服务器执行。先检查 Docker 和归档：

```bash
docker version
docker compose version
sha256sum /opt/whim/whim-images.tar
chmod 600 /opt/whim/backend/compose.yaml /opt/whim/frontend/compose.yaml
if [ -f /opt/whim/backend/.env ]; then chmod 600 /opt/whim/backend/.env; fi
if [ -f /opt/whim/frontend/.env ]; then chmod 600 /opt/whim/frontend/.env; fi
```

核对 SHA256 与本地 `Get-FileHash` 的结果一致。

### 7.1 Docker 网络

确认共享网络是否存在：

```bash
docker network inspect my-network
```

仅在网络尚不存在时创建：

```bash
docker network create my-network
```

如果现有 MySQL、Redis 容器尚未加入该网络，分别连接；已经加入时跳过：

```bash
docker network connect my-network mysql8.2
docker network connect my-network redis
```

容器名不同就替换命令中的名称，并同步修改后端 Compose 的 `MYSQL_HOST`、`REDIS_HOST`。使用外部数据库或 Redis 地址时，确保后端容器能够访问对应地址，无需执行上述容器入网命令。

### 7.2 MySQL 数据库

在 MySQL 客户端中执行以下 SQL 创建数据库，已有数据库时不要重复初始化或清空：

```sql
CREATE DATABASE IF NOT EXISTS whim
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_0900_ai_ci;
```

确认后端配置的账号可以从容器网络连接，并具备建表、变更表结构等 Flyway 迁移权限。MySQL 需要满足 `MYSQL_SSL_MODE` 对应的 TLS 配置。

后端首次启动会执行 Flyway 建表，后续启动会执行尚未应用的版本迁移，不需要手工导入迁移脚本。不要修改已执行的迁移文件。

## 八、服务器加载镜像

```bash
docker image load --input /opt/whim/whim-images.tar
docker image inspect whim-backend:local whim-frontend:local --format '{{.RepoTags}} {{.Os}}/{{.Architecture}}'
```

加载成功后应能看到两个镜像标签。加载镜像不会启动应用，也不会恢复数据库或已上传文件；这些数据需要按原目录和数据库备份单独保留。[镜像加载说明](https://docs.docker.com/reference/cli/docker/image/load/)

服务器只运行已经加载的镜像，不需要上传 Dockerfile、Java 源码、前端源码或安装构建工具。

## 九、启动并验证

先启动后端，等待健康检查通过：

```bash
cd /opt/whim/backend
docker compose config --quiet
docker compose up -d --no-build --pull never --wait --wait-timeout 300 backend
docker compose ps
docker compose logs --tail=100 backend
```

再启动前端：

```bash
cd /opt/whim/frontend
docker compose config --quiet
docker compose up -d --no-build --pull never --wait --wait-timeout 60 frontend
docker compose ps
docker compose logs --tail=100 frontend
```

`--no-build` 禁止在服务器构建，`--pull never` 禁止拉取应用镜像，`--wait` 等待服务运行或健康检查通过；等待超时后根据日志排查原因。[启动命令说明](https://docs.docker.com/reference/cli/docker/compose/up/)

检查前端和前后端链路：

```bash
curl --connect-timeout 3 --max-time 10 http://127.0.0.1:9191/healthz
curl --connect-timeout 3 --max-time 15 http://127.0.0.1:9191/api/system/auth/captcha
```

第一个请求应返回健康响应，第二个应返回后端验证码接口的 JSON。若修改了前端端口或接口前缀，要同步修改检查地址。

浏览器访问 `http://服务器IP:9191`，使用数据库中的有效账号和当次验证码登录，确认菜单、文件上传和下载正常。通过域名网关访问时，将流量转发到前端的 `9191` 端口；已有 HTTPS 网关可参考 `whim-vue/deploy/nginx/https.conf.example`。应用层请求加密不能替代 HTTPS 对响应和登录令牌的保护。

后端监控端口 `9090` 只监听容器回环地址，供健康检查使用，不发布到宿主机。浏览器访问前端时，后端接口通过 Nginx 转发，不依赖浏览器直接连接宿主机的 `9192` 端口。

## 十、持久化目录和文件存储

| 宿主机目录 | 容器目录 | 用途 |
| --- | --- | --- |
| `/opt/whim/backend/files` | `/app/data/files` | 正式文件和本地上传分片 |
| `/opt/whim/backend/logs` | `/app/logs` | 后端日志 |
| `/opt/whim/frontend/nginx/templates` | `/app/nginx-templates` | 可修改的 Nginx 模板 |

后端启动步骤自动创建根目录、设置 UID/GID `10001:10001` 的写权限，再降权运行应用。迁移进来的子目录和文件仍需具备相应权限，启动步骤不会递归修改已有文件的所有者。上传临时目录也需要可写空间。

前端首次启动会从镜像复制 Nginx 模板；服务器已有非空模板时保留原内容。因此新镜像中的模板修改不会自动覆盖服务器模板，需检查并更新保留的模板后重建前端容器。默认 `client_max_body_size` 为 `201m`。

文件管理页面读取数据库 `sys_file_storage` 的配置。Linux 容器中，本地目录应填写 `/app/data/files`；`FILE_STORAGE_PATH` 只影响文件模块的默认实例，不会替换数据库已有目录。不能把 Windows 的 `C:\...`、`D:\...` 或宿主机的 `/opt/whim/backend/files` 直接填为容器内存储路径。

从 Windows 迁移现有文件时，先停写、备份数据库和文件，完整复制原存储目录，保留存储配置 ID、相对对象路径及需要续传的 `.multipart` 目录，再按原配置 ID 调整数据库中的 `base_path` 并核对权限。已有文件或未完成任务的配置不能通过管理页面直接更改存储位置；仅新增默认配置不会迁移旧文件。

本地分片目录和正式文件目录应在同一支持原子移动的文件系统，不单独挂载 `.multipart` 到其他磁盘。合并期间还会生成完整临时文件，需要预留相应磁盘空间。多实例使用本地存储时，各实例必须能够访问同一份上传目录。

## 十一、更新、修改配置和停止服务

### 11.1 发布新版本

发布前备份数据库、上传目录和当前配置，保留上一版镜像归档。前后端涉及协议、密钥或接口变化时作为同一版本发布。

1. 在本地修改代码或构建配置，重复第四、五节，生成新的镜像归档。
2. 上传新归档到服务器；运行参数未变时不用覆盖服务器现有 Compose 和 `.env`。
3. 在服务器加载新镜像：

```bash
docker image load --input /opt/whim/whim-images.tar
```

4. 依次重新创建后端、前端容器：

```bash
cd /opt/whim/backend
docker compose up -d --no-build --pull never --force-recreate --wait --wait-timeout 300 backend
```

```bash
cd /opt/whim/frontend
docker compose up -d --no-build --pull never --force-recreate --wait --wait-timeout 60 frontend
```

5. 重复第九节的链路、登录和文件上传检查。

若需要回退，加载对应旧版归档并重建容器；已执行的数据库迁移不会随镜像回退自动撤销，需要先确认旧版应用与当前数据库兼容。

### 11.2 仅修改环境变量或 Nginx 模板

| 修改内容 | 是否需要重新构建镜像 | 操作 |
| --- | --- | --- |
| 后端数据库、Redis、JWT、上传限制、分片规则 | 否 | 更新服务器 Compose 或后端 `.env`，重新创建后端容器 |
| 前端后端地址、端口、网络、模板路径 | 否 | 更新服务器前端 Compose 或 `.env`，重新创建前端容器 |
| 服务器保留的 Nginx 模板 | 否 | 更新模板，重新创建前端容器以重新生成配置 |
| 前端公钥、标题、文案 | 是，前端 | 修改本地 `whim-vue/.env`，重新构建、导出、加载、重建前端容器 |
| 前端接口前缀 | 是，前端 | 重建镜像，并让服务器运行参数与构建前缀保持一致 |
| 后端镜像内的请求加密私钥 | 是，后端；配对公钥变化时前端也需重建 | 重新配对并协调发布 |

重新创建命令与上一小节相同。`docker compose restart` 不会应用新的容器环境变量，修改环境变量后使用 `up --force-recreate`。[重启与配置更新的区别](https://docs.docker.com/reference/cli/docker/compose/restart/)

### 11.3 停止服务

```bash
cd /opt/whim/frontend
docker compose stop --timeout 30 frontend
cd /opt/whim/backend
docker compose stop --timeout 45 backend
```

停止容器会保留挂载目录和数据库。再次启动使用第九节命令。

## 十二、常见问题

| 现象 | 检查内容 |
| --- | --- |
| 提示镜像不存在 | 是否执行了 `docker image load`；镜像标签是否与 Compose 一致 |
| 提示外部网络不存在 | 是否创建了 `my-network`；前后端网络配置是否一致 |
| 后端无法连接数据库 | MySQL 地址、端口、密码、账号授权、容器网络和 TLS 模式 |
| Redis 认证错误 | 无密码时是否误传了空密码；有认证时密码及 ACL 用户是否正确 |
| 前端构建提示公钥为空 | 是否填写 `whim-vue/.env`，是否执行读取配置的步骤并通过 `--build-arg` 传入公钥 |
| 登录请求解密失败 | 前端镜像中的公钥是否与后端实际私钥配对，浏览器是否仍缓存旧页面 |
| 前端出现 502 | 后端是否健康；`BACKEND_ADDRESS` 是否使用可达地址和正确的容器/宿主机端口 |
| 上传出现 413 | 后端 multipart、服务器保留的 Nginx 模板和外层网关限制是否足够 |
| 本地文件不可读写 | 数据库存储目录是否为容器内路径，UID/GID 10001 是否有权限 |
| 云存储凭据解密失败 | `FILE_STORAGE_SECRET_KEY` 是否缺失、变化或与原环境不一致 |
| 修改 `.env` 后没有变化 | 变量是否被 Compose 引用，是否被宿主环境覆盖，是否已重新创建容器 |
| 刷新页面后上传列表消失 | 当前浏览器队列未持久化，刷新或关闭页面不会自动恢复队列 |
