验收日期：2026-09-29。对象：本地 `8089` 服务、本地 MySQL 测试库及 Redis。最终验收使用 JDK 25 重新构建并启动的服务进程，动态测试发生在修复生效之后。

## 数据与方法

在测试库中临时建立租户 A、B，分别绑定不同套餐；建立 5 个验收用户、3 个租户角色、两个租户各自的成员关系与授权。测试数据使用独立的 `990000xx` ID。通过验证码、登录及带令牌的真实 HTTP 请求验收，同时查询 MySQL 核对拒绝操作没有写入、事务回滚恢复绑定。测试结束后删除全部临时数据库记录和强制回滚用的触发器；已核对 8 张业务表及触发器均无验收残留。未改动 Flyway 历史或初始化管理员。

完整逐项结果见[动态验收明细](阶段1-RBAC动态验收明细.json)。最终共 **83 项检查，83 项通过，0 项失败**。

## 已通过的关键行为

- Flyway V5 已执行，平台管理员可登录，未登录访问受保护接口返回 HTTP 401。
- A、B 的成员与角色列表隔离；双租户用户的两个令牌各自保持租户上下文。
- 有效功能权限是角色权限与租户套餐权限的交集；无角色、无当前租户或缺少权限时不能进入相应接口。
- 使用 A 上下文提交 B 的角色或成员 ID 时，业务层拒绝操作，B 的数据库绑定和状态没有变化。
- 角色授权、套餐授权、成员、角色、租户和全局用户状态发生有效变更后，受影响旧令牌失效；重新登录取得更新后的权限。
- 临时触发器使角色权限写入失败后，数据库事务回滚，原权限绑定和原令牌仍有效。
- 按用户名连续失败登录，第 11 次触发 HTTP 429。

## 测试中发现并修复的问题

1. **错误 HTTP 状态与响应体不一致。** 首轮有 16 项失败属于同一原因：错误响应体的 `code` 为 400、401 或 403，实际 HTTP 状态却是 200。`GlobalExceptionHandler` 的相关方法已统一返回 `ResponseEntity`。重启后，参数校验、错误密码、禁用用户和跨租户拒绝均通过 HTTP 状态与响应体一致性检查。
2. **不支持的 HTTP 方法返回 500。** `XssFilter` 在进入 Spring MVC 前预查路由，提前把方法不支持异常包装成 `ServletException`。现已让预查失败交由 `DispatcherServlet` 正常处理。重启后，对 `/system/auth/userInfo` 发出 PATCH 得到 HTTP 405，响应体 `code` 也为 405。

上述错误响应已同步到 Apifox `whim` 项目：22 个接口均补充 HTTP 405，登录接口补充禁用用户的 403，统一错误响应模型明确 HTTP 状态与 `code` 一致。

## 验收结论

阶段 1 的迁移、功能权限、租户边界、权限交集、会话失效、事务回滚、错误 HTTP 状态与登录限流均经真实接口验证；**本次阶段 1 验收通过**。已将 Spring Boot 重打包插件限定到 `whim-start`，使用 JDK 25 执行标准 `mvn clean package` 成功，随后用生成的可执行 JAR 启动服务并再次通过全部 83 项检查。服务最终健康检查为 HTTP 200，数据库与 Redis 均为 `UP`。该阶段的通过结论只覆盖功能权限 RBAC，后续数据权限仍按任务计划实施。
