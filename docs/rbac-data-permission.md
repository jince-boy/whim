# 单组织 RBAC 与数据权限

## 数据模型

账号在整个系统中唯一，用户名保存为小写。软删除后仍保留用户名唯一性，避免历史操作记录被新账号混淆。每个用户有一个主部门，可持有多个角色和多个岗位。角色授予功能权限及数据范围；岗位只表达任职关系，不自动授予角色，不改变用户主部门。

系统不再区分平台与租户，也没有租户切换、套餐、成员身份和租户开关。菜单目录只用于导航，授予目录不等于授予其子菜单和按钮。超级管理员通过内置 `superadmin` 角色识别，不依赖固定用户 ID；该角色不可编辑、停用或删除。

业务实体软删除；用户角色、用户岗位、角色权限和自定义部门关联物理删除。`createBy` 表示创建操作者，业务负责人用 `ownerUserId` 等独立字段表达，不使用创建人替代业务归属人。

## 操作与数据范围

访问必须同时满足登录身份有效、目标操作有效、实际获得该操作权限以及数据归属处于范围内。列表、分页总数、详情、更新、逻辑删除使用同一过滤机制；新增和归属变更还需要验证新归属。不同操作分别授权，例如列表权限不授予修改或重置密码权限。

功能权限统一由 Controller 的 `@SystemCheckPermission`（Sa-Token 组合注解）检查，固定角色要求使用 `@SystemCheckRole`。Service 不再逐方法调用 `requirePermission`，也不通过解析数据范围重复检查接口权限。`StpInterfaceImpl` 只向 Sa-Token 提供会话中的权限与角色；超级管理员在构建用户信息时获得全部启用权限码，不返回 `*`，因此停用或删除的操作也不能被管理员绕过。当前管理员身份通过 `AuthenticationContext` 委托 Sa-Token 判断。

权限、角色及账号授权变更仍在事务提交后调用 Sa-Token 撤销相关会话，回滚不撤销。新增权限不会自动扩大普通角色授权，已登录管理员通过刷新用户信息或重新登录获取新增权限。会话授权是请求入口的校验依据，数据范围由解析器按有效授权计算；非 HTTP 调用必须从可信且完成认证授权的业务入口进入，不能把 Service 当作开放的免鉴权接口。

角色修改、权限分配、操作范围覆盖、角色委派及管理员角色保护统一由 `ISysRoleService` 负责；用户角色分配和目标账号保护统一由 `ISysUserService` 负责；权限定义及可授予范围由 `ISysPermissionService` 维护。`ISysRolePermissionService`、`ISysUserRoleService` 仅提供关联表的通用持久化操作，不反向依赖业务服务。控制器调用对应业务服务，授权事务和数据权限注解也放在该入口上，避免跨关联服务往返和循环依赖。目标角色、目标用户及授权范围校验不能用接口权限注解代替。

| 编码 | 范围 | 规则 |
| --- | --- | --- |
| 1 | 全部 | 允许全部业务数据 |
| 2 | 自定义部门 | 仅所选有效部门，不自动包含下级 |
| 3 | 本部门 | 按当前有效账号主部门计算 |
| 4 | 本部门及下级 | 按真实父子关系递归计算有效部门 |
| 5 | 本人 | 按业务归属人列判断，不按创建人判断 |

同一个操作只合并实际授予这个操作的有效角色范围，取并集。例如 A 授予“用户列表 + 本部门”，B 授予“岗位列表 + 全部”，B 不会扩大用户列表范围。

`sys_role.data_scope` 是默认范围。`sys_role_permission.data_scope` 非空时覆盖该角色在本操作的范围；为空时继承默认值。默认自定义部门保存在 `sys_role_dept`，操作覆盖自定义部门保存在 `sys_role_permission_dept`。新角色没有任何功能授权，默认范围为本人。

`sys_permission.data_permission=1` 表示该操作使用数据权限。标注 `@DataPermission` 的方法若对应权限未登记这个标志，会拒绝执行。权限不存在、停用、账号无效、缺少授权或范围配置错误时拒绝访问。有效但为空的数据范围生成恒假条件，不回退为全部。

部门失效或祖先链断裂时，其范围不生效。部门停用、删除要求没有子部门、用户、岗位或角色范围引用。当前接口只修改名称和排序，不提供部门树迁移。创建子部门以父部门处于创建范围为前提；根部门要求全部范围。可见部门列表可能缺少父节点，展示层可将其作为当前可见树的根，不能补出未授权节点。

## 自定义业务接入

框架位于 `whim-mybatisplus`，解析契约 `DataPermissionProvider` 位于 `whim-core`。系统模块通过 `ISysDataScopeService` / `SysDataScopeServiceImpl` 实现当前操作的数据范围解析及候选授权范围计算；权限服务维护权限定义，角色服务负责委派边界，二者复用数据范围服务。数据范围服务只依赖认证抽象和内部只读 Mapper，不反向依赖角色、用户或部门业务服务。

`SysDataScopeType` 定义五种范围。解析时先按精确操作加载有效角色及覆盖配置，再分别批量加载默认自定义部门和操作自定义部门；操作覆盖严格匹配角色与权限组合，不与角色默认部门合并。候选部门和账号主部门一起沿真实父子关系向上校验，只保留整条祖先链启用、未删除且到达根节点的部门，循环、断链及超过 500 字符路径限制的节点均不产生授权。本部门及下级仅在主部门有效时向下递归一次。范围合并阶段最多四次查询，不再按角色数或祖先层级逐次往返数据库；查询返回的数据量仍取决于候选部门和组织规模。空范围保持为空，不回退为全部。范围结果不使用跨请求共享缓存，避免角色或部门变化后继续使用旧范围。

框架仍仅依赖 `DataPermissionProvider`。项目 `DataPermissionInterceptor` 继承 MyBatis-Plus 原生插件，只补充防绕过和元数据只读约束，SQL 解析与改写继续复用原生实现。`DataPermissionSqlHandler` 实现 `MultiDataPermissionHandler`，生成部门与本人条件；`@DataPermission` 建立操作范围上下文。拦截器位于分页插件之前，分页总数与结果使用同一范围；未进入受保护业务时不额外解析 SQL。认证和持久化框架不互相依赖。其他业务模块通过注解声明自己的表和归属字段，不需要修改系统数据范围服务。

在权限目录登记精确权限码，数据权限标志设为 1。在 Spring 管理的公开服务方法上声明：

```java
@DataPermission(permission = "business:order:list", tables =
        @DataPermissionTable(name = "business_order",
                departmentColumn = "dept_id", userColumn = "owner_user_id"))
```

表名、列名、别名是开发者提供的静态标识符，不接收请求内容。数组可声明多张表；`alias` 为空时匹配该表全部 SQL 别名，非空时只匹配指定别名。没有部门归属时将 `departmentColumn` 设为空；没有用户归属时将 `userColumn` 设为空；两列不能同时为空。连接和子查询须声明每张需要保护的真实业务表及正确归属。

查询、更新、删除自动附加条件。INSERT 无法仅凭查询条件证明新数据归属，新增前调用：

```java
DataPermissionContext.checkOwnership("business_order", ownerUserId, deptId);
```

迁移归属时先按操作范围读取并锁定旧记录，再校验新负责人和部门，最后更新。该检查遵守所有嵌套调用范围；同一表的嵌套 SQL 条件取交集。审批状态等业务规则由服务层处理。

通过 Spring 代理调用注解方法。同类内部调用不会重新触发注解，内部辅助方法沿用已有上下文。异步、线程池和定时任务不继承请求身份，须建立可信执行身份并通过授权入口执行，不能接受客户端提供的忽略权限标志。

内部授权元数据只读 Mapper 方法使用 `@DataPermissionMetadata`，避免授权解析和引用完整性检查被当前业务范围截断。该标记只支持方法级声明，不能用于普通业务数据接口。执行时始终核验映射语句为 `SELECT`：即使没有数据权限上下文，标记方法用于新增、修改或删除也会被拒绝；写入入口和语句准备阶段均执行检查，避免批处理、语句复用跳过只读约束。标记是开发者声明的受信任内部入口，不代表任意 SQL 都能安全豁免，新增标记仍须审查查询用途及 SQL。

受 `@DataPermission` 保护的普通业务操作不允许使用 `@InterceptorIgnore(dataPermission = "true")` 或线程级忽略策略关闭过滤；误配置会抛出 `DataAccessDeniedException`，按现有异常协议返回 HTTP 403 和 `Result.code=403`。完整业务过滤不能替换成内部元数据查询。业务 Mapper 不得通过共享二级缓存复用受限查询结果；业务缓存须包含授权范围并协调授权变化后的失效。

普通查询、加锁查询、更新和逻辑删除复用 `IService` 与条件构造器；存在性判断使用 `exists()`，无需先查全量列表。菜单目录锁和管理员角色锁也通过条件构造器查询，不另写 XML。XML 保留跨表授权查询、引用检查和部门递归等用途。更新审计字段统一交给 `MetaObjectHandler`，链式更新传入实体以触发自动填充。菜单完整编辑的可空字段通过 `@TableField(updateStrategy = FieldStrategy.ALWAYS)` 写入；状态变更使用已加载的完整实体，不能用仅带 ID 和状态的实体调用 `updateById`，以免清空其他字段。其他局部字段置空通过 Wrapper 的 `set` 显式表达。权限状态变化后的会话撤销在具体业务方法中执行，不重写通用 `updateById` 偷带业务副作用。

## 菜单导航与目录维护

`V2__menu_navigation.sql` 增加内置标志、路由唯一约束、目录事务锁和菜单管理操作。`V3__default_home_menu.sql` 将默认首页登记为普通页面菜单。`V4__restore_menu_icons.sql` 追加恢复菜单默认图标。`V5__permission_menu_management.sql` 更新内置标记的字段说明，内置语义保护与核心节点删除保护分别处理。启动应用时必须完成 Flyway V5；不修改或重用历史迁移。

登录初始化按 `GET /system/auth/userInfo`、`GET /system/permission/userMenus` 的顺序读取用户授权和菜单。导航接口只要求登录，普通角色必须直接获得页面或外链节点；只授予目录或按钮不会隐式授予页面。服务端只补齐导航所需有效目录祖先，不增加操作权限。停用或祖先链断裂的节点不参与导航；隐藏节点仍可生成授权路由。

菜单与按钮权限统一由 `SysPermissionController`、`ISysPermissionService` 管理，不再保留独立的菜单控制器和服务。管理树、新增使用 `GET/POST /system/permission`，详情、修改、删除使用 `GET/PUT/DELETE /system/permission/{permissionId}`，继续使用既有 `system:menu:list/detail/create/update/delete` 操作权限，已有角色授权无需迁移。原扁平权限选项迁至 `GET /system/permission/options`，仍要求 `system:permission:list`；状态接口保留 `PUT /system/permission/{permissionId}/status` 和 `system:permission:status`。前端页面路由仍为 `/system/menu`。

新建、删除以及通过完整编辑修改权限语义或状态仅由超级管理员执行；普通已授权管理者只能维护可委派节点的展示配置，独立状态接口仍按可委派权限校验。内置权限不可改类型、权限码或数据权限标志，但非核心内置节点可以删除。目录可以包含目录、页面和外链，页面只包含按钮；外链只接受 HTTP/HTTPS。页面路由名称和绝对路径全局唯一，保留系统静态路径。

核心节点包括内置根目录以及内置 `system:menu:*`、`system:permission:*` 操作，不能删除、停用、隐藏或迁移。响应的 `protectedNode` 标记供前端展示删除限制。节点有子节点时拒绝删除；普通叶子节点（包括非核心内置节点）可删除。删除在同一事务中清理角色操作自定义部门、角色权限关联，并逻辑删除节点；权限码仍不重复使用。角色授权、操作范围配置与菜单删除共用目录事务锁，避免并发产生无效引用。删除、权限语义或操作状态变化在事务提交后撤销受影响账号及超级管理员旧授权快照，回滚不撤销；修改展示配置不撤销会话。

前端将授权树一次解析为路由与导航节点，再派生侧栏、顶部菜单、搜索和面包屑。默认查询参数在各导航入口一致；隐藏页面保留面包屑并定位到可见祖先。路由平铺到布局下，目录层级只用于导航；页面缓存以稳定的路由包装组件名识别。标签激活由真实路由派生，同一路由查询参数变化更新同一标签地址；关闭当前页才切换到保留页。菜单保存后重新加载用户和导航，移除已撤销路由、标签和缓存。

### 首页与页面入口

首页也由 `GET /system/permission/userMenus` 返回。V3 登记的默认首页为 `home / /index`，组件路径 `layout/default/index`，对应前端 `src/views/layout/default/index.vue`，权限码为 `system:home:view`；初始只授予超级管理员，普通角色须显式授权。前端不补造首页菜单或静态首页路由。

当前在已授权、可见、组件已实现的内部页面中按后端排序选择首个页面作为默认入口。登录后的默认跳转、Logo、返回首页、固定标签和关闭全部标签共用这一入口；目录跳转排除隐藏页面、外链和未实现组件。没有可用内部页面时显示无可访问页面状态，仍可进入个人信息。

不同用户、角色的首页分配属于后续独立的首页配置功能，不在菜单表增加“是否首页”等分配字段。该功能接入时应在已授权的路由范围内选择入口，不能借首页配置授予新的页面权限。

路由重载先完整解析与检查唯一性，再替换已注册路由；失败保留原导航。退出会使旧菜单请求失效，避免旧请求恢复已退出账号的权限。标签只在导航成功后更新，关闭当前标签先导航再删除；重新授权时同步固定标签，清理失效页面和旧缓存。

## 角色与数据管理边界

普通管理员不能管理超级管理员账号，不能修改本人角色关联、本人持有角色的授权配置，不能调整本人主部门扩大范围。管理员成员变更串行执行，不能停用或删除当前账号，不能移除最后一个有效超级管理员。

普通管理员修改角色配置，须对角色包含的操作拥有全部数据范围。分配已有角色时，逐操作比较候选角色对目标用户产生的范围与操作者范围，不能证明包含关系则拒绝。“本人”数据可能分布在其他部门，不能仅凭目标用户属于可见部门就认定其全部本人数据可以委派。

角色、权限、用户状态、主部门及密码变更，在事务提交后撤销受影响账号的旧会话，回滚不撤销。数据权限解析查询当前有效授权，不只依赖登录快照。

岗位成员替换须检查岗位及全部新旧用户范围；任一目标不可见或不可用，整体拒绝，不做部分修改。无部门岗位通过全部范围或本人负责人范围访问。用户仍承担有效岗位或部门负责人职责时不能删除。

## 空库初始化与接口

空库初始化使用 `V1__initialize.sql`，菜单导航扩展使用 `V2__menu_navigation.sql`，默认首页使用 `V3__default_home_menu.sql`，菜单默认图标修正使用 `V4__restore_menu_icons.sql`，统一权限维护说明使用 `V5__permission_menu_management.sql`，要求 MySQL 8.0.16 或以上。正常启动应用时 Flyway 依次执行迁移；已有数据库只追加执行未应用的更高版本迁移。共有 11 张表和 40 个操作权限。

初始化账号 `admin`，密码 `admin123`，主部门“总部”，角色为超级管理员，密码采用 BCrypt 存储。初始化后可通过密码重置接口修改默认密码。数据库必须完全为空，包括旧 `flyway_schema_history`，不能将旧版本记录与新 V1 混用。

接口契约见 `openapi.json`，包含 46 个接口。登录不接收组织上下文；`GET /system/auth/userInfo` 无切换参数。用户部门、状态、密码、角色分别管理。角色默认范围和操作覆盖范围分别配置，操作级 `dataScope=null` 恢复继承，`deptIds` 须为空集合。

主键由 MyBatis-Plus 生成。超出 JavaScript 安全整数范围的 Long 在响应中输出字符串，前端不能强转为 Number。日期时间默认 `yyyy-MM-dd HH:mm:ss`。

业务接口、全局异常处理器和 Sa-Token 异常处理器直接返回 `Result<T>`。`whim-web` 自动配置注册 `ResultResponseBodyAdvice`，在 MVC 写出响应体前读取 `Result.code` 设置 HTTP 状态，响应内容保持原样。`code` 使用 HTTP 状态码：成功通常为 200，参数错误为 400，未登录为 401，无权限为 403，唯一约束冲突为 409，限流为 429，系统异常为 500。非 `Result` 返回类型（如文件下载）不参与此处理。

前端在 Axios 成功和异常拦截器中读取相同的 `Result` 结构；非 2xx 进入异常拦截器，消息和字段校验详情仍从响应体读取。网络或网关未返回 `Result` 时按 HTTP 状态或网络错误兜底，页面无需重复同步状态码。
