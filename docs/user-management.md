# 用户管理

用户管理采用左侧部门树、右侧分页列表。点击部门查询该部门及全部下级部门的可见用户；“全部用户”不限制部门，“未分配部门”仅查询主部门为空的用户。搜索支持用户名、姓名、联系电话、状态，切换部门回到第一页，重置搜索保留部门选择。

列表仅展示状态，行内按顺序直接显示编辑、删除、修改密码、分配角色四个操作，删除使用红色文字并保留确认弹窗。操作按权限显示，并保留本人及内置管理员保护限制。遵循前端操作列规范：不超过4项时全部直接显示，超过4项时显示前三项及第四个“更多”按钮，编辑和删除优先保留在外部。新增与编辑使用公共表单弹窗，维护姓名、主部门、多个岗位、联系方式、性别、状态和备注；岗位不隐式授予角色。用户名仅在新增时填写，统一存储为小写，删除后不可复用。创建时间复用公共审计字段与自动填充处理器。

## 接口

所有接口要求系统登录，使用 `Authorization: Bearer <accessToken>`，返回项目统一 `Result<T>`。GET 筛选通过查询参数提交，JSON 请求中 ID 和操作参数统一放在 Body。

| 方法 | 路径 | 功能权限 | 说明 |
| --- | --- | --- | --- |
| GET | /system/user/page | system:user:list | 用户分页 |
| GET | /system/user/detail | system:user:detail | 编辑回填及当前岗位 |
| POST | /system/user/add | system:user:create | 新增用户和岗位关系 |
| PUT | /system/user/update | system:user:update | 编辑资料、部门、状态与岗位 |
| PUT | /system/user/resetPassword | system:user:resetPassword | 修改密码 |
| DELETE | /system/user/delete | system:user:delete | 删除用户和关联关系 |
| GET | /system/userRole/list | system:userRole:list | 当前角色及可分配角色 |
| PUT | /system/userRole/assign | system:userRole:assign | 提交完整角色集合 |

分页使用 `pageNum/pageSize`，默认 1/10，每页最多100条。`deptId` 包含下级部门；`unassigned=true` 与 `deptId` 互斥。数据权限按当前确切操作的角色取并集，用户“本人”范围使用用户 ID，部门范围使用主部门 ID。

新增必须提供 `username/name/password`，性别、状态省略时默认0，岗位省略时默认为空集合。编辑必须提供 `id/name/gender/status`。`deptId/email/phone/remark` 省略或 null 表示清空，`postIds` 省略或空数组表示清空岗位，不能为 null。角色接口只接收 `id/roleIds`，角色集合省略或空数组表示清空，不能为 null。岗位与角色集合最多100项，元素不能为 null。

请求不接收审计字段；响应不包含密码或密码哈希。密码保留原输入，长度8～72个字符，不包含空白，UTF-8编码最多72字节，使用现有 BCrypt 工具保存哈希。详情返回现有停用岗位用于回显，新增任职必须校验岗位、部门分支的有效性与本次操作的数据范围。

## 关系和授权约束

- 用户最多有一个主部门，也可以未分配部门。正常用户的主部门及全部祖先必须正常。
- 用户调部门、停用或删除前，检查是否仍担任部门负责人；存在负责人关系时拒绝操作，先在部门管理中调整负责人。
- 内置 `admin` 账号仅允许本人维护。其他账号（包括其他超级管理员）不能读取其编辑详情、查询或调整其角色，也不能修改资料、密码或删除该账号；前端禁用对应操作，后端返回403。
- 普通管理员不能修改、删除其他超级管理员账号或修改其密码、角色。角色候选包含可授予的正常角色与已有角色，已有不可调整角色只读并必须保留。
- 超级管理员可以向其他可管理用户分配正常角色；其他管理员只能调整自己当前持有的非超级管理员角色。不能调整当前账号的角色，也不能删除、停用当前账号。`admin` 本人可以修改个人资料、密码、部门和岗位，仍须通过归属、部门有效性、岗位和负责人关系校验；其他账号不能自行改变部门、岗位。
- 用户资料修改、密码修改、角色变化与删除完成后，在事务提交后失效目标用户全部登录会话。角色无变化时不重复写入或失效会话。
- 用户写入、岗位关系和角色关系维护共用现有组织锁与服务事务；删除用户时原子移除岗位和角色关系，保留用户名全局唯一约束。
- 参数校验失败返回400，未登录401，功能权限、归属或可授予角色越权403，用户名冲突409，记录不可见及业务约束失败500，HTTP状态与 Result.code 一致。

部门树复用部门查询接口，岗位选项复用岗位分页接口并支持搜索与继续加载；分别需要 `system:dept:list` 和 `system:post:list`。没有候选查询权限时保留原有归属与岗位回显，不静默清空。
