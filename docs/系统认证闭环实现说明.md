# 系统认证闭环实现说明

## 1. 实现范围

本次实现完成了 Whim 当前阶段的系统账号认证闭环：

```text
登录请求
  -> 登录频率限制与 GIF 验证码一次性校验
  -> 查询用户
  -> 校验用户状态
  -> BCrypt 校验密码
  -> 查询有效租户并确定当前租户
  -> 按当前租户查询角色和权限
  -> AuthenticationSession 创建 Sa-Token 会话
  -> 将 UserInfo 写入当前 Token-Session
  -> 返回 token
```

当前已经完成租户列表、初始租户选择和基于 `userInfo` 的租户上下文选择。默认租户字段可读取，但个人信息修改和默认租户设置接口暂不提供。数据权限 SQL 隔离尚未实现。

## 2. 改动文件

### 2.1 认证抽象层

文件：`whim-framework/whim-core/src/main/java/com/whim/core/auth/AuthenticationContext.java`

`AuthenticationContext` 只负责读取当前请求的认证身份，提供：

- 当前用户信息；
- 登录状态；
- 当前用户 ID；
- 当前部门 ID；
- 当前租户 ID；
- 当前账号体系；
- 当前角色信息；
- 超级管理员判断。

登录、退出和 token 读取不属于认证上下文职责，已从该接口移出。

文件：`whim-framework/whim-core/src/main/java/com/whim/core/auth/AuthenticationSession.java`

新增认证会话操作抽象：

- `login(UserInfo userInfo, boolean rememberMe)`：创建登录会话并返回通用令牌信息；
- `updateUserInfo(UserInfo userInfo)`：更新当前令牌独立的用户认证上下文；
- `logout()`：注销当前登录会话；
- `kickout(String loginType, Collection<Long> userIds)`：强制指定账号体系下的用户退出全部登录会话。

文件：`whim-framework/whim-core/src/main/java/com/whim/core/auth/model/AuthenticationToken.java`

通用认证令牌包含：

- `tokenType`：令牌类型；
- `accessToken`：访问令牌；
- `expiresIn`：剩余有效期，单位为秒。

文件：`whim-framework/whim-core/src/main/java/com/whim/core/auth/model/UserInfo.java`

新增当前用户展示信息：

- `name`：真实姓名
- `avatar`：头像地址
- `tenantIds`：当前用户可访问的有效租户 ID 集合
- `defaultTenantId`：用户默认进入的租户 ID，仅在默认租户仍可访问时返回
- `currentTenantId`：当前 Token 正在操作的租户 ID，平台上下文或等待用户选择时为空

文件：

- `whim-modules/whim-system/src/main/java/com/whim/system/model/enums/SysUserStatus.java`

新增系统用户状态枚举：

- `SysUserStatus`：`ENABLED(0)`、`DISABLED(1)`。

用户状态字段仍保留 `Integer` 数据库类型，避免扩大 MyBatis 映射和接口序列化改动；业务判断通过枚举的 `matches` 方法完成，不再直接比较魔法数字。用户性别属于业务字典，`gender` 仅保存字典编码，不使用 Java 枚举固化字典项。

### 2.2 Sa-Token 实现层

文件：`whim-framework/whim-satoken/src/main/java/com/whim/satoken/context/AuthContext.java`

该类只负责基于 Sa-Token 读取当前登录身份：

- 获取当前登录用户；
- 获取当前用户 ID 和账号体系；
- 判断登录状态；
- 判断当前用户是否为超级管理员。

文件：`whim-framework/whim-satoken/src/main/java/com/whim/satoken/session/SaTokenAuthenticationSession.java`

该类实现 `AuthenticationSession`，负责：

- 根据账号体系创建 Sa-Token 会话；
- 处理 `rememberMe`；
- 将 `UserInfo` 写入当前 Token 独立的 Token-Session；
- 支持在租户切换后更新当前 Token-Session；
- 返回通用 `AuthenticationToken`；
- 注销当前会话；
- 通过 Sa-Token `kickout(loginId)` 强制指定用户的全部终端下线。

文件：`whim-framework/whim-satoken/src/main/java/com/whim/satoken/constants/AuthSessionKeys.java`

集中维护 Sa-Token Session 中的登录用户上下文键，避免认证上下文、会话实现和权限适配器之间散落相同字符串。

文件：`../whim-framework/whim-satoken/src/main/java/com/whim/satoken/service/StpInterfaceImpl.java`

权限适配器从当前请求的 Token-Session 读取用户上下文，并校验其中的用户 ID 与 Sa-Token 传入的 `loginId` 一致，再读取：

- `permissionCodeSet`；
- `roleCodeSet`。

这样同一账号在多个终端使用不同 Token 时，可以分别选择不同租户，角色和权限不会在终端之间互相覆盖。

### 2.3 用户和角色查询层

文件：`whim-modules/whim-system/src/main/java/com/whim/system/mapper/SysUserMapper.java`

新增：

```java
SysUser selectByUsername(String username);
```

对应 XML 查询 `sys_user` 中未逻辑删除的用户。

文件：`whim-modules/whim-system/src/main/java/com/whim/system/mapper/SysRoleMapper.java`

新增：

```java
List<RoleInfo> selectRoleInfoListByUserIdAndTenantId(Long userId, Long tenantId);
```

查询用户已启用角色的：

- 角色 ID；
- 角色名称；
- 角色编码；
- 数据权限范围 `dataScope`。

文件：

- `whim-modules/whim-system/src/main/resources/mapper/SysUserMapper.xml`
- `whim-modules/whim-system/src/main/resources/mapper/SysRoleMapper.xml`
- `whim-modules/whim-system/src/main/resources/mapper/SysPermissionMapper.xml`

查询规则包括：

- 排除逻辑删除用户、角色、权限和关联关系；
- 排除停用角色和权限；
- 租户上下文存在时，只加载当前租户角色、权限及全局角色；
- 租户上下文为空时，只加载平台全局角色和权限；
- 先查已启用角色，再从结果中提取角色 ID、角色编码和角色详情，避免重复查询角色表；空角色编码不进入返回的角色信息，但该角色原有的权限关系仍按既有规则计算；
- 权限查询复用已启用角色 ID，只连接用户角色、角色权限和权限三张表；同一权限可由多个角色授予，因此权限编码继续使用 `DISTINCT` 去重；
- 过滤空角色编码和权限编码。

文件：

- `whim-modules/whim-system/src/main/java/com/whim/system/mapper/SysUserTenantMapper.java`
- `whim-modules/whim-system/src/main/resources/mapper/SysUserTenantMapper.xml`

提供用户可访问租户 ID 和租户列表查询。查询从 `sys_user_tenant.user_id` 开始，排除已删除的关联关系，并只返回未删除、已启用且未过期的租户。超级管理员可以读取全部有效租户。ID 查询只取 ID，供登录和访问校验使用；列表查询取下拉框展示字段，供 `userInfo` 使用，避免每次登录读取租户名称等额外数据。

角色查询用两表连接校验用户角色关系和角色状态；权限查询复用该结果，不再重复连接角色表，最多连接三张表。超级管理员判断改为两表查询加 `LIMIT 1`，不再嵌套 `EXISTS`。租户关系查询保留必要的两表连接，以校验租户启用状态和有效期。现有索引包含 `sys_user_role(user_id, deleted, role_id, tenant_id)`、`sys_role_permission(role_id, tenant_id, deleted, permission_id)` 和 `sys_user_tenant(user_id, tenant_id)`，查询从用户 ID 或关联键收敛。

返回 `SysUser`、`SysTenant` 和 `RoleInfo` 的 XML 查询使用显式 `resultMap`；返回字符串、数字和布尔值的查询仍使用标量 `resultType`。登录用户名查询只读取认证所需字段，不再带出邮箱、手机号和审计字段。

### 2.4 认证服务层

文件：`whim-modules/whim-system/src/main/java/com/whim/system/service/impl/AuthServiceImpl.java`

登录流程现在为：

1. 按连接地址和用户名限制登录频率，并根据验证码 UUID 与连接地址一次性校验 GIF 验证码；
2. 按用户名查询用户；
3. 用户不存在或 BCrypt 密码不匹配时统一抛出 `UserPasswordNotMatchException`，响应文案为“用户名不存在或密码错误”；
4. 密码正确但用户已禁用时抛出 `UserDisableException`；
5. 构建 `UserInfo`；
6. 有效默认租户优先作为当前租户；没有有效默认租户且只有一个可访问租户时自动进入；多个租户且没有默认值时等待用户选择；
7. 按当前租户加载角色和权限；
8. 调用 `AuthenticationSession.login`；
9. 将通用 `AuthenticationToken` 转换为登录响应。

同时新增：

- `logout()`：注销当前会话；
- `getUserInfo(Long tenantId)`：统一返回当前用户信息和右上角可选租户列表；传入租户 ID 时校验访问权并切换，不传时按有效默认租户（无默认且仅有一个可用租户时按唯一租户）刷新当前 Token 的授权信息；

`AuthServiceImpl` 分别依赖两个职责明确的抽象：

- `AuthenticationContext`：读取当前用户；
- `AuthenticationSession`：登录、退出、创建令牌和强制用户下线。

文件：`whim-modules/whim-system/src/main/java/com/whim/system/service/impl/SysPermissionServiceImpl.java`

权限更新使用 `updateById` 成功写入后，会根据权限 ID 查出当前拥有该权限的用户，并调用 `AuthenticationSession.kickout` 强制这些用户的全部终端下线。用户下一次请求时，Sa-Token 会返回“token 已被踢下线”，重新登录后加载最新权限。

关联用户查询在 `SysPermissionMapper.xml` 中完成，查询同时校验角色、用户角色关系和角色权限关系的有效状态，并按用户 ID 去重。

### 2.8 模块依赖边界

- `whim-core` 定义认证上下文、认证会话和账号体系常量，不依赖 Sa-Token 或 MyBatis-Plus；
- `whim-satoken` 只依赖 `whim-core`，负责认证实现，不依赖 `whim-mybatisplus`；
- `whim-mybatisplus` 只依赖 `whim-core`，负责持久化基础设施，不依赖 `whim-satoken`；
- `whim-system` 依赖 `whim-core`、`whim-mybatisplus`、`whim-redis` 和 EasyCaptcha，只通过核心抽象操作认证会话，不再引用 Sa-Token 类型；
- `whim-start` 作为应用组装层，同时引入 `whim-system`、`whim-satoken` 和 Web 模块。

认证上下文已经由账号级 Account-Session 调整为令牌级 Token-Session。部署该版本时，旧版本签发的 Token 不包含新的令牌级上下文，应让存量登录用户重新登录，避免继续使用旧会话。

## 3. 接口清单

认证接口前缀：`/system/auth`。

### 3.1 用户登录

先获取 GIF 验证码：

```http
GET /system/auth/captcha
```

接口返回 `data.uuid`、`data.image`（GIF 图片的纯 Base64 编码，不含 Data URL 前缀）和 `data.expiresIn`（120 秒）。前端显示图片时可将 `data:image/gif;base64,` 拼接在 `data.image` 前面。图片显示四位字母数字，输入时不区分大小写。

验证码答案保存在以 UUID 和客户端连接地址组成的 Redis 键中，有效期两分钟。登录时使用提交的 UUID 和当前连接地址查找，并原子取出删除；答案错误、连接地址不匹配和重复提交都需要重新获取。这里使用服务端 `getRemoteAddr()`，不信任客户端自行提交的 IP 请求头。如果应用位于反向代理后，连接地址可能是代理地址；此时该绑定按代理地址生效。

```http
POST /system/auth/login
Content-Type: application/json
```

请求体：

```json
{
  "username": "admin",
  "password": "admin123...",
  "uuid": "<验证码接口返回的 UUID>",
  "captchaCode": "<GIF 图片中的四位字符>",
  "rememberMe": true
}
```

示例密码是 `V5__initialize_admin.sql` 新建 `admin` 时使用的初始密码，末尾包含三个英文句点；已有 `admin` 账号不会被迁移重置密码。

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `username` | 是 | 5 到 18 位用户名 |
| `password` | 是 | 8 到 18 位明文密码 |
| `uuid` | 是 | 验证码接口返回的 UUID |
| `captchaCode` | 是 | GIF 图片中的四位字母数字，不区分大小写 |
| `rememberMe` | 否 | 是否持久化登录状态 |

验证码获取按连接地址每分钟最多 60 次；登录按连接地址每分钟最多 60 次、按用户名每分钟最多 10 次。超过限制返回 HTTP 429。用接口工具调试时，获取验证码与提交登录需要使用相同的服务端连接地址。

成功响应示例：

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "tokenType": "Bearer",
    "accessToken": "登录令牌",
    "expiresIn": 604800
  },
  "success": true
}
```

后续请求需要在请求头中携带：

```http
Authorization: Bearer 登录令牌
```

用户名不存在或密码校验失败时，响应体中的 `code` 均为 `401`，响应消息统一为“用户名不存在或密码错误”，不会通过响应内容暴露用户名是否存在。

### 3.2 获取当前用户或选择租户

```http
GET /system/auth/userInfo
Authorization: Bearer 登录令牌
```

不传 `tenantId` 时，使用用户仍有权访问的默认租户；没有有效默认租户但仅有一个可用租户时，使用该唯一租户；有多个可用租户且未设置默认值时，`currentTenantId` 为空，等待用户选择。

右上角选择租户时仍调用同一接口：

```http
GET /system/auth/userInfo?tenantId=10001
Authorization: Bearer 登录令牌
```

传入 `tenantId` 后，系统重新校验成员关系、租户状态和有效期，再按目标租户更新当前 Token-Session 中的角色、权限和角色数据范围。无权访问或租户不可用时返回 HTTP 403。

成功响应中的 `data` 为 `AuthUserVO`，其中 `tenantList` 直接提供右上角租户下拉选项。前端切换租户后直接使用本次响应更新用户状态；后续如果再次不带参数调用，会重新回到默认租户，而不是保留上次手动选择。

该接口受 `/system/**` 登录拦截器保护，未登录请求会返回 HTTP 401。

该接口按当前前端约定同时承担上下文选择，调用会修改当前 Token-Session；前端不应预取该接口。设置了默认租户的超级管理员不传参数时也会进入默认租户；没有有效默认值且可用租户不止一个时才进入空租户的平台上下文。本阶段不提供修改 `defaultTenantId` 的接口。

### 3.3 退出登录

```http
POST /system/auth/logout
Authorization: Bearer 登录令牌
```

成功响应：

```json
{
  "code": 200,
  "message": "退出登录成功",
  "data": null
}
```

退出后，当前 Sa-Token 会话失效，继续使用旧 token 将无法通过登录校验。

## 4. 权限校验行为

登录成功或切换租户时，系统会将当前租户对应的角色和权限写入当前 Token 独立的 Sa-Token Token-Session。

超级管理员角色 `superadmin` 在 Sa-Token 权限适配器中返回通配权限 `*`；普通用户只返回当前租户查询得到的权限编码，避免跨租户权限合并。

现有注解可以继续使用：

```java
@SystemCheckLogin
public Result<?> currentUser() {
    // 业务代码
}

@SystemCheckPermission("system:user:list")
public Result<?> listUser() {
    // 业务代码
}

@SystemCheckRole("admin")
public Result<?> updateSystemConfig() {
    // 业务代码
}
```

Sa-Token 的请求拦截规则目前是：

- `/system/**` 默认要求登录；
- `/system/auth/login` 放行；
- `/system/auth/captcha` 放行；
- `/error` 和 `/` 按配置放行；
- 权限和角色注解由 Sa-Token 注解策略处理。

## 5. 数据库前置条件

登录前需要准备以下数据：

1. `sys_user` 中存在未删除用户；
2. 用户 `status = 0`；
3. 用户密码使用 BCrypt 存储；
4. 用户通过 `sys_user_role` 关联有效角色；
5. 角色 `status = 0` 且 `deleted = 0`；
6. 角色通过 `sys_role_permission` 关联有效权限；
7. 权限 `status = 0` 且 `deleted = 0`。

`V1__baseline.sql` 只初始化了系统配置，没有初始化管理员用户、角色和权限数据。因此部署后仍需要准备认证基础数据，否则登录时会统一提示“用户名不存在或密码错误”，或登录成功后没有任何角色和权限。

数据库结构已经由 Flyway 管理，不再需要手工执行本次默认租户字段 SQL：

- 空数据库首次启动：依次执行 `V1__baseline.sql`、`V2__add_user_default_tenant.sql`；
- 已有表但尚无 `flyway_schema_history` 的数据库：以版本 1 建立基线，再执行 `V2__add_user_default_tenant.sql`；
- 已由 Flyway 管理的数据库：只执行版本号高于当前版本的新迁移；
- 每次执行结果、版本、校验和会记录在 `flyway_schema_history`。

`V2` 在执行前会检查 `default_tenant_id` 是否已存在，因此此前已经手工添加过该字段的数据库也可以安全完成首次接管。

Flyway 只能管理已经存在的数据库实例和其中的表结构，因此 MySQL 中仍需预先创建 `MYSQL_DB` 指定的数据库，默认名称为 `whim`。

`baseline-on-migrate` 默认开启是为了让当前既有数据库能够无人工介入地接入 Flyway。所有既有环境完成首次接管后，生产环境应设置 `FLYWAY_BASELINE_ON_MIGRATE=false`，防止误连接到非空但未纳管的数据库时自动建立基线。

后续数据库变更必须新增更高版本的迁移文件，例如 `V3__create_tenant_context.sql`。已经在任一环境执行过的版本化迁移禁止修改、删除或复用版本号。

## 6. 当前边界和注意事项

本次实现完成的是系统认证基础闭环，不代表多租户数据权限已经完成。

当前仍然存在以下边界：

- 当前数据库缺少明确的用户部门归属关系，因此 `deptId` 暂时不能可靠填充；
- `dataScope` 已加载到 `RoleInfo`，但还没有转换为 SQL 数据权限条件；
- MyBatis-Plus 尚未接入统一的数据权限拦截器；
- 权限实体修改后，相关用户会被强制下线并在重新登录时加载最新权限；角色授权关系变更入口尚未实现，因此该入口后续也必须复用相同的强制下线机制。

因此，下一阶段应在当前认证闭环之上补充：

```text
角色数据范围计算
  -> 用户/部门查询的数据权限条件
  -> MyBatis-Plus 数据权限拦截
```
