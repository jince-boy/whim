# 默认租户与可选多租户

Whim 的 RBAC 授权以租户为作用域。只需要单组织 RBAC 的项目也使用一个内部默认租户：用户归属该租户，角色和套餐在该租户内授权，登录时自动进入。使用方无需先创建租户或每次手动选择租户。需要多租户时，再创建其他租户并配置其成员、套餐和角色；用户只能进入可访问的租户。两种用法共用一套授权模型，不靠全局关闭租户检查来切换模式。

## 初始化

Flyway `V7__bootstrap_default_tenant.sql` 在 `V5` 平台管理员与 `V6` 组织字段之后执行。只有数据库尚无任何租户、尚无名为 `Whim 默认套餐` 的套餐，并且有效的 `admin` 账号已绑定有效平台 `superadmin` 角色时，才创建以下数据：

| 对象 | 初始值 |
| --- | --- |
| 租户 | 编码 `default`，名称 `默认租户`，正常状态，无到期时间 |
| 套餐 | `Whim 默认套餐`，包含迁移执行时已有且启用的非平台 `system:%` 权限 |
| 管理员 | `admin` 加入默认租户，获得 `tenant_admin` 角色；原平台超级管理员身份保留 |
| 角色 | `tenant_admin` 的数据范围为当前租户全部，权限与初始套餐一致 |
| 登录默认值 | `admin.default_tenant_id` 原本为空时设为默认租户 ID |

已有租户的部署跳过整组初始化，不新增租户、不改管理员默认租户。编码或套餐名被占用时也跳过，保留原有数据。该迁移只在执行时授予目录中已有的权限。后续 V8 为 V7 建立的默认租户继续授予内置岗位功能权限；其他新权限必须通过套餐和角色显式授权，或由明确限定目标的后续迁移授予。迁移不会为已有业务数据猜测租户归属。

## 使用方式

- **仅使用 RBAC：** 保持一个默认租户。把普通用户加入该租户，再分配角色与套餐允许的权限。用户仅有一个可访问租户时，登录会自动选中它。
- **使用多租户：** 创建其他租户并分配套餐、成员和角色。同一用户可以加入多个租户，按有权访问的租户切换。当前令牌使用目标租户的角色、权限和部门。管理员的默认租户不限制其访问其他获授权租户。
- **平台管理：** `admin` 仍有平台超级管理员角色。平台功能权限与租户角色授权分别判断；平台身份不能替代某个业务动作的数据范围。默认租户管理员角色只得到非平台权限。

`V7` 解决初次安装没有租户、只有 RBAC 的场景。本地数据库已记录成功的 V7，默认租户登录和岗位样本的租户隔离已通过真实 HTTP 验收。阶段 2 的六种范围及组织管理接口仍需完整应用级矩阵；阶段 4 的通用执行层与其他租户业务资源尚未完成。默认租户的存在本身不能证明所有业务数据安全。
