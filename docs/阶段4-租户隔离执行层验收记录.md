# 阶段 4：租户隔离执行层验收记录

## 执行边界

`whim-mybatisplus` 只对已审查的独立租户业务表 `sys_post` 追加当前租户 SQL 条件。租户 ID 来自 `whim-core` 的 `AuthenticationContext`，模块不依赖 Sa-Token、HTTP 请求或系统领域服务。缺少登录、未选择租户时，受保护表的查询、修改、删除和插入均拒绝；后台任务和虚拟线程如未建立有效认证上下文，也不能隐式访问受保护表。当前没有通用绕过开关。

受保护表的插入不允许显式提供 `tenant_id`，由拦截器填入当前租户；修改语句不允许改变租户列。岗位创建服务仍先计算本次功能动作的数据范围，校验部门，再由拦截器写入租户字段。这样可避免直接调用 Mapper 时用显式租户列跳过 MyBatis-Plus 的默认插入处理。SQL 层租户隔离只是兜底；岗位与成员的部门和本人范围由各自业务查询及写目标校验承担。

拦截器顺序为租户隔离、分页、乐观锁、防全表操作。单元测试检查了顺序、未登录/空租户、租户切换、嵌套调用、虚拟线程、普通查询、COUNT、联表别名、插入及更新租户列的拒绝。三项单元测试全部通过。现有实体未声明 `@Version`，因此乐观锁只完成安装与顺序核对；当前岗位写入仍通过 ID、租户和动作范围的最终 SQL 条件约束。防全表插件是通用防护，业务范围不能依赖它推导。

实际 HTTP 与数据库回归覆盖岗位六范围 168/168、岗位接口 42/42、岗位成员 45/45、部门六范围 57/57、成员六范围 52/52、组织接口 38/38、会话 54/54、记住我 9/9、租户到期 6/6，共 **471/471** 项；连同 RBAC 回归 83/83，总计 **554/554** 项。岗位软删还核对了删除人、删除时间和删除后不可见；分页总数与列表范围一致。当前没有对外导出接口。所有动态脚本为本地验收工具，使用测试数据库，执行后清理夹具。

## 索引与执行计划

本地测试库临时插入 3000 条岗位后，对真实查询形态执行 `EXPLAIN`，随后删除全部 3000 条夹具，见[执行计划明细](阶段4-SQL执行计划明细.json)。按租户排序的列表使用 `idx_post_tenant_sort`；按创建人统计使用 `idx_post_tenant_creator`；按 ID 详情和范围写入使用主键。部门列表在该数据量和 `ORDER BY sort,id LIMIT 10` 下由优化器选择租户排序索引，再过滤部门；`idx_post_tenant_dept` 仍为不按排序取全量部门数据的路径提供前缀索引。成员与授权关联表已有租户、部门、角色和权限的组合索引；当前测试库规模不足以把某个计划视为生产数据量下的固定计划，因此未因一次 `EXPLAIN` 盲目新增索引。

全局身份表、部门认证引导表和平台/租户混合表没有使用统一租户插件。其业务入口明确检查当前租户与授权动作，避免全局账号被错误过滤或平台上下文被当作某个租户。
