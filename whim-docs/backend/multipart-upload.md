# 分片上传与断点续传

文件功能由三层组成：

- `whim-file`：可复用存储能力，`MultipartFileStorage` 适配本地、MinIO、OSS。
- `whim-file-management`：个人任务、分片约束、并发协调、完成确认及过期清理。
- `whim-start` 与 `whim-vue/src/views/file/upload`：受保护的接口和“我的文件”页面。

普通流式上传仍使用 [文件存储](/backend/file-storage) 中的 `FileStorageService.upload`。新任务流程用于需要进度、暂停和续传的非空文件；小文件可以只有一个分片。

## 默认配置

```yaml
file:
  upload:
    maximum-file-size: 1GB
    part-size: 8MB
    concurrency: 3
    maximum-active-tasks: 10
    maximum-pending-bytes: 5GB
    task-lifetime: 24h
    signature-lifetime: 5m
    cleanup-delay: 60000
```

Spring 的 MB/GB 数据大小单位按二进制换算，页面显示为 MiB/GiB。

| 配置                  | 约束                                                         |
| --------------------- | ------------------------------------------------------------ |
| maximum-file-size     | 单文件总大小，默认 1 GiB，不超过一万个分片                   |
| part-size             | 5–16 MiB，默认 8 MiB，最后一片可以更小                       |
| concurrency           | 前端同时上传的分片数，1–6，默认 3                            |
| maximum-active-tasks  | 每用户活动任务上限，1–100，默认 10                           |
| maximum-pending-bytes | 每用户活动任务声明的总容量上限，默认 5 GiB，不小于单文件上限 |
| task-lifetime         | 自创建起的固定有效期，1 小时至 7 天；续传不延长              |
| signature-lifetime    | 分片直传地址有效期，30 秒至 15 分钟                          |
| cleanup-delay         | 清理调度间隔，毫秒，默认 60000                               |

`file.storage.max-file-size` 仍约束普通上传，默认 20 MiB；它不等于分片任务的总大小上限。`spring.servlet.multipart` 约束单次本地分片请求，默认 20 MiB 能容纳 16 MiB 分片及 multipart 包装。

服务器选择默认存储、对象键和分片大小，客户端不能指定服务器目录或切换任务的存储。改变配置后，旧任务仍使用创建时保存的存储平台、配置名称和分片大小。

## 上传流程

1. 浏览器在 Worker 内分块计算原文件的 SHA-256，作为重选文件的指纹。
2. 生成请求标识并创建任务；同一用户重复提交同一请求标识返回同一任务。
3. 查询服务器确认的已上传分片，跳过已经完成的部分。
4. 每片先计算 MD5 和 SHA-256，登记内容约束，获取该片的传输方式。
5. 本地存储使用应用分片接口；MinIO、OSS 使用短期签名地址直传。
6. 全部上传后请求完成。服务器读取真实分片清单、核对长度和校验值，再执行合并。
7. 核对正式对象大小后，任务变为 `COMPLETED`。

任务 ID、文件指纹、存储原生 upload ID 的用途不同。任务视图不单独暴露原生 upload ID，但云端签名 URL 的查询参数会包含它，应将整个签名 URL 作为临时凭据保护。指纹不能用于授权或跨用户秒传。

### 校验的准确含义

- 原文件 SHA-256 在浏览器计算，用于确认续传时选中的文件与原文件相同。数据库中该字段是客户端声明，不能作为“服务端已经计算并验证完整文件 SHA-256”的证明。
- MinIO 初始化 SHA-256 分片校验，签名绑定 `x-amz-checksum-sha256` 和 `Content-Length`。查询与合并使用存储返回的 SHA-256 和 ETag。
- MinIO 9.0.3 预签名会忽略 `Content-MD5`，因此实现没有用它承担 MinIO 的签名内容约束。
- OSS V4 签名绑定 `Content-MD5`，并通过 additionalHeaders 绑定 `Content-Length`；OSS 校验收到的分片。MD5 用于与存储协议兼容的传输完整性检查，不用于身份认证或安全内容判定。
- 本地分片写入时校验 MD5 和 SHA-256，合并时再次校验，正式文件只在完整合并后原子发布。
- ETag 仅用于提供商的合并协议，不统一解释为整个文件的 MD5。

浏览器自动根据 Blob 发送 Content-Length。前端不手动设置这个受限请求头，也不对签名 URL 解码、修改主机或重新拼接参数。

## 状态与恢复

| 状态       | 含义与允许操作                                       |
| ---------- | ---------------------------------------------------- |
| CREATED    | 任务已入库，存储初始化尚未完成，可恢复初始化或取消   |
| UPLOADING  | 可以申请分片签名、上传、查询进度、完成或取消         |
| COMPLETING | 合并意图已提交，允许重复确认结果；禁止取消或追加分片 |
| COMPLETED  | 文件可下载，重复完成请求返回相同记录                 |
| CANCELING  | 取消意图已提交，清理失败后调度会重试                 |
| CANCELED   | 已执行取消，仍可能等待签名过期后的补充清理           |
| EXPIRED    | 未完成任务超过固定有效期                             |
| FAILED     | 已明确确认分片会话丢失，需要重新创建任务             |

暂停是客户端停止发送数据，不修改服务器任务状态。暂停时可能有某个分片刚好抵达服务器，因此继续上传前始终重新查询进度。

页面刷新后从服务器任务列表选择“选择原文件续传”。浏览器必须重新获得用户对原文件的访问授权；校验完整指纹后才上传剩余片。没有在 localStorage 保存令牌、签名 URL 或原文件内容。

### 失败窗口

任务创建、合并意图、取消意图分别先提交，再执行下一阶段。数据库事务与对象存储操作不能组成同一个分布式事务：

- 合并成功但数据库提交失败：保留 COMPLETING，下次先查询正式对象并核对大小，再补记完成。
- 完成响应在网络中丢失：重复调用完成接口，返回已经确认的任务。
- 合并前缺少分片：保持 UPLOADING，继续补传。
- 已明确丢失上传会话：确认最终对象不存在后进入 FAILED；不会把鉴权错误或网络故障当成丢失。
- 文件大小与记录不符：不发布为完成，保留任务并记录错误，供运维排查。
- 云端初始化成功、upload ID 回写前发生进程崩溃：可能留下数据库无法定位的孤儿会话，必须由桶生命周期兜底清理。

### 多实例协调

要求 MySQL 8.0+，使用 InnoDB 行锁及 NOWAIT。任务状态变更获取任务排他锁，本地分片写入获取任务共享锁和单片排他锁，不同分片可并行。同用户创建任务时另有额度锁，防止并发绕过数量及声明容量限制。

锁由数据库连接持有，进程退出或事务结束后自动释放，没有依赖内存锁或仅靠会过期的 Redis 锁。冲突返回 429，前端进行有限退避重试。

为防止取消与外部写入交错，部分阶段在持有行锁时进行存储操作；该阶段会占用一个数据库连接。事务超时为 300 秒，SDK 配置连接和读写超时。事务超时不等于可以强制中断任意磁盘操作或外部 InputStream；部署时应使连接池容量、上传并发和存储吞吐匹配。

多实例本地存储必须挂载同一支持跨实例一致读写及原子移动的持久卷，且配置名称、根目录一致；任务之间的协调由数据库行锁负责。独立的本机目录不能跨实例恢复，部署在临时容器文件系统上也不能保证重启后分片仍存在。

## 清理与资源边界

调度默认每分钟执行，每轮最多处理 20 个任务。合并中的任务先恢复结果，其余任务按状态、有效期清理。失败任务保留重试信息并轮换，避免长期占据批次头部。

本地的分片、未写完分片和合并临时文件都位于 `.multipart/<taskId>`。清理只处理该任务目录中的普通文件，不跟随链接，不递归删除正式文件目录。

取消后先终止原生上传，再等待最后签名过期加 10 分钟的在途窗口，重复清理后标记 cleaned，并删除数据库分片约束。正式文件和任务记录保留，取消不是删除已经完成的文件。

对象存储必须配置“终止未完成分片上传”的生命周期规则，作用于本模块对象前缀。默认任务有效期 1 天时，可以设置 3 天兜底；调整任务有效期时应留出恢复时间。该规则用于清理未知 upload ID 和超长在途请求，不应设置为自动删除已完成文件。

用户额度约束的是活动任务和声明容量。签名绑定单片长度，完成阶段再检查实际长度。已经完成文件的长期保留、总存储预算和桶配额由部署及业务保留策略管理。

## 接口与权限

所有接口均要求系统登录，并使用项目的系统权限注解。任务归属在服务层按当前用户限制，超级管理员也不能用个人文件接口访问他人的任务。这是固定的个人归属模型，不按角色的部门数据范围扩大可见性。

公共前缀为 `/system/fileUpload`：

| 方法   | 路径                                         | 权限后缀 | 作用                                   |
| ------ | -------------------------------------------- | -------- | -------------------------------------- |
| GET    | /options                                     | list     | 上传参数                               |
| GET    | /tasks                                       | list     | PageQueryDTO 分页查询本人任务          |
| POST   | /tasks                                       | upload   | 幂等创建                               |
| GET    | /tasks/{taskId}                              | list     | 任务和已确认分片                       |
| POST   | /tasks/{taskId}/resume                       | upload   | 恢复初始化                             |
| POST   | /tasks/{taskId}/parts/{partNumber}/signature | upload   | 固定摘要并申请签名                     |
| PUT    | /tasks/{taskId}/parts/{partNumber}           | upload   | multipart/form-data，本地分片字段 file |
| POST   | /tasks/{taskId}/complete                     | upload   | 校验并确认完成                         |
| DELETE | /tasks/{taskId}                              | cancel   | 取消未完成任务                         |
| GET    | /tasks/{taskId}/download                     | download | 本人文件流式下载                       |

完整权限为 `system:fileUpload:<后缀>`。文件页面所需角色应同时授予 list 和相应操作权限。

JSON 响应使用 `Result<T>`；分页使用 `PageDataVO<T>`。错误 HTTP 状态与 Result.code 一致：400 参数或状态不符、401 未登录、403 无权限/非本人、409 唯一约束冲突、413 上传请求过大、429 任务忙或额度不足、500 存储及系统故障。二进制下载已经开始后发生的传输故障无法再改写为完整 JSON 响应。

[下载完整 OpenAPI 文档](/openapi/file-upload.json)。

## 前端使用与下载

“我的文件”由迁移脚本登记为后端菜单，路由 `/files`，组件 `file/upload/index`。同时补齐只读 `GET /system/permission/userMenus`，从当前登录权限快照构建页面及有效祖先树，不添加菜单管理权限要求。更新部署后刷新用户资料或重新登录，以取得新增页面权限。

前端一次处理一个文件，文件内部按配置并发上传；最多自动重试 3 次，之后保留可重试状态。切换页面、退出账号时停止活动传输，签名地址的请求不携带应用 Authorization。

文件以附件方式下载，并发送 nosniff。支持 File System Access API 的 HTTPS Chrome/Edge 可直接流式写盘；不支持该能力的浏览器使用最多 20 MiB 的缓冲下载，大文件显示明确提示。下载接口提供完整文件流，本轮没有实现 HTTP Range 下载续传或秒传。

## 云端部署配置

- MinIO 必须支持 SHA-256 multipart checksum，账号具备创建、查询分片、上传分片、完成、终止及对象读取权限。
- OSS 使用 V4、正确地域、静态凭据及对应桶权限。凭据只配置在服务端。
- 签名 endpoint 必须是浏览器和应用均可访问的地址；HTTPS 页面必须使用 HTTPS 存储地址。
- CORS 精确允许前端 Origin，允许 PUT，允许 Content-Type、Content-MD5、x-amz-checksum-sha256 请求头。浏览器自行处理预检，网关不能改写已签名的内容长度或校验头。进度与 ETag 以服务器查询为准，不依赖浏览器读取 ETag。
- 桶保持私有，不把本地存储根目录映射成公开静态资源。
- 应用实例与对象存储保持时钟同步，并配置上述未完成分片生命周期。
- 本地根目录只允许应用写入。路径校验不能替代文件系统权限隔离；底层卷必须支持原子移动。
